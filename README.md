# HPWD Data Manager

히트펌프 건조기 실험 데이터 통합 분석 프로그램

BR (BlackRose) + AMS + MX100 + NIDAQ 데이터를 병합하고, 열역학 계산을 수행한 뒤,
개별선도 / 습공기 선도 / P-h 선도 / 성능 비교로 시각화합니다.

> **저장소: `kimjy2576/HPWD-DataManager` (비공개)**
> **기본 포트: 8001** (사용 중이면 8002~ 자동 변경)

---

## 실행 방법

폴더의 **`run.bat` 더블클릭** — 이게 전부입니다.

`run.bat`이 자동으로:
1. Python 확인 (3.10+)
2. 패키지 확인 → 없으면 자동 설치
3. 방화벽 규칙 등록 (관리자 권한일 때)
4. **서버 모드로 실행** → 다른 PC에서도 접속 가능

실행하면 CMD에 두 주소가 표시됩니다:
```
  이 PC에서 접속:   http://localhost:8001
  다른 PC에서 접속: http://192.168.0.15:8001   ← 이 주소를 공유
```

> **최초 1회만** `run.bat` 우클릭 → **"관리자 권한으로 실행"** 하면
> 방화벽 규칙이 자동 등록됩니다.
> 안 해도 실행되며, Windows 방화벽 팝업에서 **[액세스 허용]** 눌러도 동일합니다.

> **PowerShell**에서는 `.\run.bat` 으로 입력 (앞에 `.\` 필수)

### 이 PC에서만 쓰고 싶을 때
```
python run.py
```
(`--share` 없이 실행하면 localhost 전용)

## 설정/데이터 저장 위치

| 항목 | 위치 | 비고 |
|------|------|------|
| 프로그램 코드 | 작업 폴더 | git pull로 업데이트 |
| 사용자 설정 (디폴트/슬롯) | `config/saves/`, `config/viewer_default.json` | 서버 저장 |
| 병합/계산 결과 | `results/` (+ 원본 케이스 폴더에 사본) | 서버 PC |
| Visualization 폴더 | `results/` 안의 실제 하위 폴더 | 서버 PC (모든 접속자 공통) |
| 사이드바 너비 | 브라우저 localStorage | **PC/브라우저별** |

> 📁 Visualization의 폴더는 `results/` 안의 **실제 폴더**이고, 탐색기처럼 **상위·하위 폴더가 트리로** 보입니다
> (하위 폴더는 한 단계씩 안쪽으로 들여 쓰고, 폴더 옆 숫자는 하위 폴더까지 합친 케이스 수).
> - **하위 폴더 만들기**: 폴더 줄의 `+📁` (맨 위 폴더는 툴바의 `+ 폴더`). 이름에 `/` 를 넣으면 여러 단계를 한 번에 (예: `2026-11/건조A`).
> - **옮기기**: 케이스·폴더 줄을 끌어다 다른 폴더 줄에 놓으면 그 안으로 옮겨집니다. 접힌 폴더 위에 잠시 머물면 펼쳐지고,
>   맨 위로 꺼낼 때는 끄는 동안 툴바에 나타나는 `⤒ 여기에 놓으면 맨 위로` 에 놓습니다. 케이스 줄의 폴더 선택(`📁 A / B`)으로도 옮길 수 있습니다.
> - 폴더 체크박스는 **하위 폴더의 파일까지** 한 번에 선택합니다.
> - 이름 변경(✏️)·이동·삭제가 디스크에 바로 반영됩니다. 케이스/파일 이름을 바꿀 때 **원본 케이스 폴더의 사본도 같이 바꿀지** 선택할 수 있습니다.
> - 폴더를 지우면 안의 파일과 하위 폴더는 **한 단계 위(상위 폴더)** 로 올라갑니다 (맨 위 폴더면 `results/` 바로 아래, 파일은 지워지지 않음).
>   옮겨 둔 파일은 Merge·Calculation을 다시 돌려도 그 폴더에 저장됩니다.
> - `_` 로 시작하는 폴더(`_diagnose` 등)는 프로그램용이라 목록에 나오지 않습니다.

> ⚠️ Visualization의 **사이드바 너비**는 브라우저에 저장 → PC/브라우저 바뀌면 초기화.
> 차트 **카테고리/변수/Y축 범위/글꼴**은 **[⭐ Viewer 디폴트 저장]** 으로 서버 저장 → 다른 PC에서도 불러오기 가능.

## 읽을 수 있는 파일 형식

| 소스 | 기본 확장자 | 비고 |
|------|------|------|
| BR | `.csv` | |
| AMS | `.csv` | **파일명에 AMS 가 있으면 AMS** (`.csv`·`.tsv`·`.txt`·`.dat`, 예: `AMS_log.csv`, `260311_AMS.dat`, `AMS 1.csv`), 그 밖엔 헤더 내용으로 판별 |
| MX100 | `.xls` / `.xlsx` | 엑셀만 |
| NIDAQ (일반 계측) | `.tsv` | |
| (자동) | **`.dat`** | 규칙에 없어도 **내용으로 판별** → AMS 형식이면 AMS, 그 밖의 표 형태 계측 데이터는 NIDAQ 로 병합 |

`.csv`/`.tsv` 가 아닌 텍스트 계측 파일(`.dat`, 그리고 식별 규칙에 넣은 `.txt` 등)은 **구분자(탭·쉼표·세미콜론·공백), 헤더 줄 위치,
앞쪽 설명 블록, 헤더 아래 단위 줄, 인코딩(UTF-8·CP949·UTF-16), 소수점 쉼표**를 자동으로 판별합니다.
(`.txt` 는 메모일 때가 많아 자동 판별에서 뺐습니다 — 쓰려면 Setting > 파일 식별 규칙에서 소스의 확장자에 `.txt` 추가)
어떻게 읽었는지는 Merge 로그에
`[read_dat] … 텍스트 표로 읽음 — 구분자 탭, 헤더 3번째 줄, 단위 줄 1개 건너뜀 …` 처럼 표시됩니다.

- 시간 열: `Time`·`TIMESTAMP`·`Date/Time`·`시간` 등 이름으로 찾고, 날짜/시각이 두 열이면 합칩니다.
  `오전/오후` 표기, 엑셀 날짜 일련값, LabVIEW·Unix 시각(숫자)도 시계 시각으로 바꿉니다.
  **경과 시간(0, 1, 2 … 초)만 있는 파일은 다른 소스의 시계 시각과 맞출 수 없으니** 기준 시간축을 NIDAQ 로 두거나 단독으로 병합하세요.
- **바이너리 `.dat`**: AMS 프로그램 파일이면 **같은 폴더의 측정 프로젝트 파일(`.proj`)로 바로** 읽습니다 — 아래 [AMS 바이너리 .dat](#ams-바이너리-dat).
  다른 장비의 바이너리는 측정 프로그램에서 CSV/텍스트로 내보내세요. 읽지 못하는 파일은 케이스 확정 시
  "병합에 쓰이지 않는 데이터 파일" 로 이유와 함께 표시됩니다.
- 특정 소스로 고정하고 싶으면 Setting > 파일 식별 규칙에서 그 소스의 확장자에 `.dat` 를 넣으면 됩니다 (MX100 제외).

### AMS 바이너리 .dat

**AMS 측정 폴더를 그대로 케이스 폴더에 넣으면 됩니다** — `AMS_Data.dat` 와 같은 폴더에 있는 프로젝트 파일(`*.proj`)의
채널 목록으로 기록 배치를 계산해 바로 읽습니다 (형식 학습·CSV 내보내기 불필요).
방식은 팀 변환 코드([hpwd-studio-task #13](https://github.com/kimjy2576/hpwd-studio-task/issues/13), `.dat` + `.proj` → `AMS_Data.csv`)와 같고,
같은 파일을 넣었을 때 **모든 열·값이 그 코드의 CSV 와 같습니다** (`ams_proj.py`).

- 기록 = `[시각 8바이트 double][채널…][끝 1바이트]`. 일반 계측 채널(전력계·유량계·온도 등)은 4바이트 float,
  `STX`~`ETX` 는 제품 통신 패킷(길이 = ETX 의 Number) — 패킷 안 값(RPM·압축기 Hz·EEV·덕트 온도·행정 정보 …)은 변환 코드의 바이트 위치 그대로 풉니다.
- 변환 코드와 다른 점: Time 에 **날짜까지** 넣고(`2026-11-20 10:00:00.123`), PC 시간대와 상관없이 같은 시각이 나옵니다
  (변환 코드의 `−9시간` 은 한국 시간 PC 기준). `FanSpeed`·`SuperHeatDegree` 는 값은 같고 이름만 `FanSpeed[/100]`·`SuperHeatDegree[*10]` —
  AMS CSV 와 같은 배율 표기라 Setting 의 AMS 배율이 그대로 적용됩니다 (팬 rpm, 과열도 K).
- 계측 채널 이름은 변환 코드 규칙대로 정리됩니다 (`전력`→`Active Power`→Po_WD, `소비전력량`→`Watt_Hour`→E_WD, 냉수 유량→`cold_water` …).
- Merge 로그: `[ams_dat] AMS_Data.dat: 프로젝트 파일 ○○.proj 의 채널 배치로 읽음 (…행 × …열, 기록 …바이트 …)`,
  [파일 선택] 목록에는 `(프로젝트 파일 ○○.proj 로 읽음)`.
- 맞는지 확인은 변환 코드만큼 느슨하게 합니다 — 기록의 절반 넘게 시각 값이 있고 대부분 늘어나면 맞는 배치로 봅니다.
  **0 으로 채운 기록**(파일 끝에 미리 잡아 둔 자리 등)·**다른 시각 기준일**(1904·1601 등)·**바뀌는 STX 바이트**도 읽습니다.
  시각 값이 없는 기록은 빼고 읽습니다 (변환 코드는 `00:00:00` 줄로 쓰거나, NaN 시각에서 멈춤).
  시각 확인이 안 돼도 `.proj` 로 계산한 기록 길이가 파일 크기를 딱 나누면 변환 코드처럼 그대로 읽고 로그에 ⚠️ 를 남깁니다.
- `.proj` 가 여러 개면 `.dat` 와 가장 잘 맞는 것을 자동으로 고릅니다. AMS 버전에 따라 끝 바이트가 없으면 자동 보정.
- 그래도 "맞지 않음" 이면 [파일 선택] 목록·케이스 줄(마우스 올림)에 `기록 ○바이트로 읽으면 시각 값 있음 ○% · 증가 ○% …` 처럼
  이유가 나옵니다 — `diagnose.bat` 에 `.dat` 를 끌어놓아도 같은 내용이 리포트에 나옴.
- `.proj` 가 없으면 아래 **형식 학습**으로 읽을 수 있습니다.

**어떤 변수를 읽나** — 계측 채널(전력계·유량계·온도 등)은 `.proj` 에 정의된 것을 **전부** 읽습니다.
통신 패킷(STX~ETX)은 `.dat` 안에 이름 없이 바이트로만 들어 있어, 변환 코드처럼 **정해진 바이트 위치의 48개 값**만 꺼냅니다.
[파일 선택] 의 `.dat` 줄 **📋 .proj 채널** 을 누르면 `.proj` 에 정의된 채널 전체(속성 그대로)와 앱이 읽는 것(✓)이 표로 나오고,
패킷 채널의 숫자 속성이 변환 코드의 바이트 위치와 맞는지(= `.proj` 에 위치 정보가 있는지) 자동으로 확인해 줍니다.
위치·크기 정보가 `.proj` 에 있으면 패킷 변수 전부를 읽도록 넓힐 수 있습니다 (`diagnose.bat` 리포트에도 같은 내용).

**케이스 확정 때 `.proj` 감지** — 바이너리 `.dat` 가 있는 케이스 줄에 바로 표시됩니다 (마우스를 올리면 파일별 내용).

| 표시 | 뜻 |
|------|------|
| 🟩 `AMS ← .dat (.proj ✓)` | `.dat` 를 같은 폴더 `.proj` 로 읽음 |
| ⬜ `AMS ← CSV (.dat·.proj 도 있음)` | 같은 측정의 CSV 를 읽음 (Setting › AMS 파일 = CSV). `.dat` 도 읽을 수 있는 상태 |
| ⬜ `.dat 1개 .proj 없음 → AMS ← CSV` | `.proj` 가 없어 `.dat` 는 못 읽지만 같은 측정의 CSV 로 병합 |
| 🟨 `⚠️ .dat 1개 .proj 없음` / `.proj 안 맞음` | 이 케이스의 AMS 데이터를 읽을 수 없음 → `.proj` 를 넣거나 형식 학습 |

**Setting › 처리 모드 › AMS 파일** — 같은 측정의 `.dat` 와 CSV 가 둘 다 있을 때 어느 쪽을 읽을지 고릅니다.

- **CSV 로 읽기** (기본): AMS 프로그램·변환 코드로 내보낸 CSV. **.dat 로 읽기**: 측정 원본 `.dat` 를 `.proj` 로 (날짜·밀리초까지).
- 이름이 같거나(`AMS_Data.dat`↔`AMS_Data.csv`), 이름이 달라도 **시간이 대부분 겹치고 변수가 비슷하면** 같은 측정으로 봅니다.
- 한쪽만 있으면 그 파일을 읽고, `.dat` 를 고른 상태에서 `.dat` 를 못 읽으면(.proj 없음) CSV 를 씁니다. [파일 선택] 에서 케이스마다 바꿀 수도 있습니다.
- 바꾼 뒤에는 Merge 탭에서 **케이스 확정**을 다시 누르세요.
- 변환 코드 CSV 의 `FanSpeed`(값 /100)·`SuperHeatDegree`(값 ×10)는 읽을 때 `FanSpeed[/100]`·`SuperHeatDegree[*10]` 로 이름만 맞춥니다 —
  예전엔 배율 표기가 없어 팬 rpm 이 1/100, 과열도가 10배로 나왔음. 이제 **.dat 로 읽든 CSV 로 읽든 병합 결과가 같습니다**.

#### .proj 가 없을 때: 형식 학습

같은 측정을 AMS 프로그램이 CSV 로 내보낸 파일과 비교해 형식을 학습합니다.
학습은 서버 PC 안에서만 이뤄지고 데이터는 밖으로 나가지 않습니다. **형식마다 한 번만** 하면 됩니다.

1. AMS 프로그램에서 `.dat` 하나를 CSV 로 내보냅니다 (같은 케이스 폴더에 두면 편함). 측정이 길고 상태가 여러 번 바뀐 파일일수록 좋습니다.
2. Merge 탭에서 **케이스 확정** → 그 케이스의 **[파일 선택 ▾]** → `.dat` 줄 아래 "같은 측정을 AMS 에서 내보낸 CSV" 에서 CSV 를 고르고 **[형식 학습]**.
   (다른 폴더의 CSV 는 "경로 입력" 으로 지정)
3. `✅ 형식 학습 성공` 이 나오면 끝 — 이후 **같은 형식의 `.dat` 는 케이스 폴더에 넣기만 하면** AMS 로 병합됩니다. Merge 로그에 `[ams_dat] … 학습한 형식으로 읽음`.

- `diagnose.bat` 에 `.dat` 를 끌어놓아도 같은 학습을 합니다 (같은 폴더에 **같은 이름**의 CSV 가 있을 때).
- 학습 결과(형식 정보)는 `config/ams_dat_formats/` 에 저장됩니다. 개별 측정값은 들어가지 않습니다
  (들어가는 것: 기록 안 위치·형식·배율, 상태 이름표, 다른 파일이 같은 형식인지 확인하는 데 쓰는 열별 최소~최대 범위).
  diagnose.bat 을 다른 PC 에서 돌렸다면 그 `.json` 을 서버 PC 의 같은 폴더로 복사하세요.
- 검증: 학습한 형식으로 `.dat` 를 다시 읽어 CSV 와 **모든 행을 비교**하고, 값·시각이 99.5% 이상 맞을 때만 저장합니다.
- 학습 파일에서 **값이 계속 일정했던 열**(히터가 내내 꺼져 있었다든지)은 위치를 특정할 수 없어 빠집니다.
  그 값이 변하는 다른 측정의 (.dat, .csv) 쌍으로 한 번 더 학습하면 형식 정보에 추가됩니다.
- 모델·AMS 버전이 바뀌어 형식이 달라지면 그 형식으로 다시 학습하면 됩니다 (형식 정보가 여러 개 있어도 파일마다 맞는 것을 찾음).
- 압축되었거나 길이가 제각각인 패킷 형식이면 학습이 실패하고 이유(형식 서명·엔트로피·반복 기록)가 나옵니다 → 그 내용을 공유해 주세요.
- 같은 케이스에 `.dat` 와 **같은 측정의 CSV** 가 함께 있으면 같은 데이터가 두 번 병합되지 않도록 `.dat` 는 기본으로 빠집니다
  ([파일 선택] 에서 바꿀 수 있음).

### 케이스 파일 고르기

케이스 확정 후 각 케이스의 **[파일 선택 ▾]** 를 누르면 폴더 안 데이터 파일 목록이 나옵니다.

- **체크 = 병합에 사용**, 옆 목록에서 **소스(BR / AMS / MX100 / NIDAQ)** 를 바꿀 수 있습니다 (자동 판별이 틀렸거나, 규칙에 없는 파일을 쓰고 싶을 때).
- 파일명에 AMS 가 있는 파일은 기본으로 **AMS** 로 잡힙니다. 바이너리 `.dat` 는 같은 폴더의 `.proj` 로 읽히면 `(프로젝트 파일 ○○.proj 로 읽음)`,
  `.proj` 도 학습한 형식도 없으면 ⚠️ 와 [형식 학습] 이 함께 나옵니다 (그 전에는 읽을 수 없어 병합에서 빠지고, Merge 로그에 이유가 남음).
- 고른 내용은 **Merge 와 변수 스캔에 그대로** 쓰입니다 (변수 목록이 이미 있으면 '변수 스캔' 을 다시 누르세요).
- **같은 소스 파일이 여러 개일 때 (BR·AMS)** — 파일마다 첫·마지막 시각과 열 구성을 읽어 자동으로 판단합니다.
  - 시간이 **이어지는 파일**(로그가 여러 파일로 나뉜 것)은 **하나로 이어 붙여** 병합 1회 — 예: BR 1개 + AMS `.dat` 3조각 → 병합 1회
  - 시간이 **겹치는데 변수가 다른 AMS 파일**(같은 시험을 동시에 기록한 다른 로거·보드)은 **나란히 병합** —
    파일마다 따로 전처리해서 1초 시간축에 맞춘 뒤 열을 합칩니다. 케이스 줄에 `AMS 2개 → 동시 기록 2묶음 나란히` 로 표시
    (조각으로 나뉜 동시 기록 파일이면 `A1 + A2 ‖ B1 + B2` 처럼 묶음마다 이어 붙인 뒤 나란히)
  - 시간이 떨어진 BR 파일들은 **각각 병합**하고, AMS 파일은 **시간이 겹치는 BR 파일과 짝**지음 (이름 순서와 상관없음)
  - 시각을 읽을 수 없는 파일(경과 시간만 있는 AMS 등)은 이름 순서로 처리하고 안내가 뜸
  - 케이스 줄에 `→ 병합 N회 · AMS 3개 이어 붙임` 처럼 계획이 보이고, [파일 선택] 에서 **자동 / 전부 하나로 이어 붙이기 / 파일마다 따로** 를 고를 수 있음
  - MX100·NIDAQ 은 고른 파일 전부가 매번 합쳐집니다.
  - 읽지 못한 파일 하나 때문에 케이스 전체가 멈추지 않습니다 — 그 파일만 빼고 병합하고 로그에 `⚠️ … 빼고 병합` 이 남습니다.

### 변수 스캔

- **선택한 모든 케이스의 모든 파일**(위에서 고른 대로)을 읽어 변수 목록을 만듭니다. 파일·케이스마다 변수가 달라도 전부 나옵니다.
- 표 위에 `📄 스캔: 케이스 2개 · 파일 5개 (BR 2 · AMS 3) → 변수 29개` 처럼 무엇을 읽었는지 나오고, **[파일별 보기]** 로 파일마다 변수 수를 볼 수 있습니다.
- **읽지 못한 파일**은 ⚠️ 상자에 이유와 함께 표시됩니다 (예: 학습한 형식과 맞지 않는 AMS `.dat`).
- 같은 소스 파일이 여럿인데 **일부 파일에만 있는 변수**는 소스 칸 아래에 파일 이름이 붙고, 검색창 옆 **파일 목록**으로 한 파일의 변수만 볼 수 있습니다.
- 케이스가 아주 많으면 40초까지만 읽고 몇 개 케이스를 읽었는지 알려 줍니다.
- 같은 소스 파일이 여러 개이거나 형식 학습이 필요한 `.dat` 가 있는 케이스는 확정할 때 목록이 펼쳐져 있습니다 (앞의 3개 케이스까지).

## 데이터 진단 (diagnose.bat)

Merge 결과가 이상하거나 오류가 날 때, **데이터를 밖으로 보내지 않고** 원인을 찾는 도구입니다.

`diagnose.bat` 위에 **AMS 파일, `.dat` 계측 파일, 케이스 폴더를 끌어다 놓으면** 앱과 같은 코드로 읽어서 요약 리포트를 만듭니다.
리포트는 `results/_diagnose/` 에 저장되며, **원본 값 없이 개수·칸 수·시간 길이·주요 변수 집계값만** 담깁니다.
(`.dat` 는 형식 확인용으로 바이너리 여부·구분자·헤더 위치·첫 줄·열 이름·시간 간격을 표시)
그 텍스트만 공유하면 됩니다. 파일/폴더 이름·첫 줄·열 이름까지 가리려면 `python tools\diagnose.py <경로> --mask`.

점검 항목: 헤더/데이터 칸 수 불일치, 중간 헤더 반복, 잘린 줄, 인코딩 혼재, 문자 혼입, 센서 무효값(65535),
배율(×10 저장 의심), 필수 변수 누락, 시간 형식·롤오버·역행·공백, 케이스 내 파일 분할/짝 불일치, 느린 파서 전환

## 문제 해결

| 증상 | 해결 |
|------|------|
| PowerShell에서 `run.bat` 인식 안 됨 | **`.\run.bat`** 또는 탐색기 더블클릭 |
| 다른 PC에서 접속 안 됨 | `run.bat` 우클릭 → 관리자 권한으로 1회 실행 (방화벽 등록) |
| clone 시 인증 실패 | Username=`kimjy2576`, Password=**토큰**(`ghp_...`). 비밀번호 아님 |
| `Authentication failed` | 토큰 만료/권한 부족 → 새 토큰 발급 (`repo` 체크) |
| `python` 인식 안 됨 | Python 재설치 + "Add to PATH". 또는 `py run.py --share` |
| `git` 인식 안 됨 | Git for Windows 설치 후 CMD 재시작 |
| `ModuleNotFoundError: uvicorn` | `python -m pip install -r requirements.txt` |
| CoolProp 설치 실패 | Python 3.11 사용 (3.13 미지원) |
| MX100 변수 안 잡힘 | `pip install xlrd` |
| 포트 충돌 | 자동으로 다음 포트 사용 (조치 불필요) |
| 화면 빈 페이지 / 변경 반영 안 됨 | Ctrl+F5 (강력 새로고침) |
| `git pull` 충돌 | `git stash` → `git pull` → `git stash pop` |
| Merge 결과가 이상함 / 원인 불명 | `diagnose.bat` 에 파일을 끌어놓고 리포트 확인 |
| `.dat` 파일이 병합에 안 들어감 | 케이스 확정 시 노란 "병합에 쓰이지 않는 데이터 파일" 안내 확인 (바이너리·NIDAQ 꺼짐 등). `diagnose.bat` 에 끌어놓으면 구조 확인 |
| AMS `.dat` 가 미분류 / "읽을 수 없음" | AMS 측정 폴더의 **프로젝트 파일(`.proj`)을 `.dat` 와 같은 폴더에** 두기 ([AMS 바이너리 .dat](#ams-바이너리-dat)). `.proj` 가 없으면 [파일 선택] 에서 같은 측정의 CSV 로 형식 학습 |
| 한 케이스에 같은 소스 파일이 여러 개 | 시간으로 자동 판단(이어지면 이어 붙임, 동시에 기록한 다른 AMS 는 나란히). 다르게 하려면 [파일 선택](#케이스-파일-고르기) 에서 방식 선택·파일 체크 |
| 변수 스캔에 어떤 파일 변수가 안 보임 | 표 위 ⚠️ 상자에 그 파일을 못 읽은 이유가 나옴 (AMS `.dat` 면 같은 폴더에 `.proj` 가 있는지). 소스가 틀렸으면 [파일 선택] 에서 고친 뒤 재스캔 |
| `run.bat` 실행 후 바로 닫힘 | CMD에서 `python run.py --share` 직접 실행 → 실제 오류 확인 |
